#### Как постороена регистрация и авторизация
В папке app/reg_auth хранится файл, который содержит эндпоинты для регистрации и авторизации.

##### О регистрации
- От клиента приходят логин и пароль
- Если заданного логина нет в системе, то регистрируем пользователя
- Пароль в бд хранится в зашифрованном виде
- В качестве ответа пользователю отправляются access и refresh токены. Токены подписываются секретным ключом из файла .env и хранят с прочей информацией user_id.

##### Об авторизации
- Проверяем валидность логина
- Проверяем, что переданный пароль и пароль из бд совпадают. Тут используем специальную фунцицю verify для сверки, так как пароль в бд зашифрован
- В случае успешной авторизации выдаём пользователю токены


#### JWT
В app/work_with_tokens хранится код для работы с токенами.

- функции для генерации access и refresh токенов
- ручка для обновления access токена по refresh
- функция для проверки токенов переданных от клиента

Для обеспечения безопасности доступа к данным, каждый запрос пользователя сопровождается проверкой валидности токена.
В токен зашит user_id для удобства последующих запросов к бд

#### Работа с записями пользователя
В app/records хранится файл, который предоставляет эндпоинты для создания, просмотра, обновления и удаления задач

#### Выдача доступа:
В app/records_access хранится файл, который содержит эндпоинты для выдачи другим пользователям доступа к записям и последующей работы с ними.
Для отслеживания выданного доступа в бд создана отдельная таблица, о которой говорилось выше
